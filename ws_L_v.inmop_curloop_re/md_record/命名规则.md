# 命名规则（ws/ 目录）

> 记录日期：2026-09-23
> 用途：统一 `ws/` 下模式模块的命名，便于按 mode 号查找与阅读
> 关联：`md_record/模式文件改名对照表.md`（文件与宏前缀的改名记录）

---

## 一、三层命名空间

```
Foc_<模块>_<动作>()     模式模块 / 共享核心的对外函数
g_<模块>_<量>          全局变量
FOC<NN>_<宏>           编译期宏
```

**模式模块的 `<模块>` = 文件名去掉 `foc_` 与 mode 号后的部分**。

## 二、宏：`FOC<NN>_`（已全部落地，979 处）

| mode | 前缀 | mode | 前缀 |
|---|---|---|---|
| 24 | `FOC24_` | 31 | `FOC31_` |
| 25 | `FOC25_` | 32 | `FOC32_` |
| 26 | `FOC26_` | 40 | `FOC40_` |
| 27 | `FOC27_` | 41 | `FOC41_` |
| 28 | `FOC28_` | 45 | `FOC45_` |
| 29 | `FOC29_` | 30 | `FOC30_` |

**规则**：`FOC` + 两位 mode 号 + `_` + 宏名，**全大写**。

## 三、函数：`Foc_<模块>_<动作>()`

### 3.1 模块名对照（与文件名一致，不带冗余编号）

| 文件 | 函数前缀 |
|---|---|
| `foc_20_cal.c` | `Foc_Cal_` |
| `foc_23_align.c` | `Foc_Align_` |
| `foc_24_dcal.c` | `Foc_Dcal_` |
| `foc_25_calangle.c` | `Foc_CalAngle_` |
| `foc_26_olf.c` | `Foc_Olf_` |
| `foc_27_dcl.c` | `Foc_Dcl_` |
| `foc_28_dci.c` | `Foc_Dci_` |
| `foc_29_drun.c` | `Foc_Drun_` |
| `foc_30_ramp.c` | `Foc_Ramp_`（原 `Foc_Zizeng_`，去拼音） |
| `foc_31_iqpi.c` | `Foc_IqPi_` |
| `foc_32_lockiq.c` | `Foc_LockIqPi_` |
| `foc_40_speed.c` | `Foc_Speed_` |
| **`foc_41_drun.c`** | **`Foc_Drun41_`** ⚠️ 见下 |
| `foc_45_smo.c` | `Foc_Smo45_` |

⚠️ **mode 29 与 41 的函数前缀冲突**：两者文件都叫 `foc_*_drun.c`，去掉编号后都是 `Foc_Drun_`。
**现行处理：29 用 `Foc_Drun_`，41 保留编号 `Foc_Drun41_`**（因为 41 = 29 + 前馈，是后加的特例）。
若要彻底消除，可把 `foc_41_drun.c` 改名为 `foc_41_ffdrun.c`（feedforward drun），前缀随之改为 `Foc_FfDrun_`。

### 3.2 统一动作词表

| 动作 | 统一形式 | 说明 |
|---|---|---|
| 启动 | `Foc_Xxx_Start(void)` | ⚠️ **动词必须在模块名之后** |
| 停止 | `Foc_Xxx_Stop(void)` | 同上 |
| 每拍 | `Foc_Xxx_Step(const stc_i_data_t *)` | 20 kHz ISR 中由 `Foc_Isr` 分发 |
| 初始化 | `Foc_Xxx_InitPids(void)` | 仅带 PI 的模块需要 |
| VOFA | `Foc_Xxx_VofaFill(int32_t *cur)` | 返回通道数；0 = 用通用布局 |
| 设值 | `Foc_Xxx_SetYyy(...)` | |
| 取值 | `Foc_Xxx_GetYyy(...)` | |

**反例（历史遗留，已修）**：`Foc_StartAlign` / `Foc_StartIqPi` / `Foc_StartZizeng` / `Foc_StopZizeng`
—— 动词在前，与其余 14 个模块不一致，2026-09-23 已统一。

## 四、共享核心（不加 mode 号）

| 文件 | 前缀 | 职责 |
|---|---|---|
| `foc_core.c` | `Foc_Core_` | 共享状态、过流保护、PWM 启停、Clarke/Park 助手 |
| `foc_math.c` | `Foc_Math_` / `Foc_Clarke` / `Foc_Park` / `Foc_Svpwm` | 数学与变换 |
| `foc_obs.c` | `Foc_Obs_` | RTT 观察、事件快照、模式交接 |
| `foc_pll.c` | `Foc_Pll_` | 锁相环 |
| `foc_smo.c` | **`Foc_Smo_`** | 滑模观测器 |

### ⚠️ `Foc_Smo_` 与 `Foc_Smo45_` 必须区分

| | 含义 | 归属 |
|---|---|---|
| `Foc_Smo_*` | **无感观测器本体**（被 mode 45 使用，也可被未来模式复用） | 共享层 |
| `Foc_Smo45_*` | **mode 45 自己的控制逻辑**（速度环/电流环/自动爬坡） | 模式模块 |

两者是**不同层次**，不可合并。同理 `Foc_Pll_*`（共享）与 mode 45 的用法。

## 五、变量：`g_<模块>_<量>`

### 5.1 现状（**刻意不改**）

多数模式变量仍带 mode 号：`g_speed40_*` / `g_drun29_*` / `g_dcal24_*` / `g_smo45_*`。

**为什么不统一**：这些是 **Keil Watch 的运行时接口**。改名会让
所有 Watch 表达式、断点、历史调参记录、文档引用全部失效 ——
代价高、收益低。**规则只对新代码生效。**

### 5.2 新代码规则

```
模式模块的全局量：g_<模块小写>_<量>        例：g_dci_i_ref_ma
共享核心的全局量：g_foc_<量>               例：g_foc_id_ma / g_foc_ialpha
```

**模块小写名的取法**：与函数前缀对应，全小写。
`Foc_Dci_` ↔ `g_dci_`；`Foc_Speed_` ↔ `g_speed_`（新代码）。

## 六、文件

```
foc_<NN>_<简称>.c/h       模式模块，NN = 两位 mode 号
foc_<名称>.c/h            共享核心（无编号）
```

**简称选词**：英文缩写，**不用拼音**（`zizeng` → `ramp`）。
简称与函数前缀保持一致：`foc_28_dci.c` ↔ `Foc_Dci_` ↔ `FOC28_`。
