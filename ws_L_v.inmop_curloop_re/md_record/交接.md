## 七、mode 31 方向随机 → 已解决（两次根因，均已提交）

1. **框架锚定错配**：三模块相对计数器零点各不相同（mode 30 永不复位 / 32 每次复位 /
   31 每次复位），跨模块搬运 offset 必带随机框架误差——这同时解释了 ±90° OC 失败和
   历史上 mode 31 随机初始方向。**现行约定：mode 32 注入 off_inject=0，mode 31 启动清零
   自己的相对计数；off=0 只在 32→31 自动交接链上有效**（转子必须仍停在 VERIFY 吸附位）。
2. **伪翻转**：方向检查基准 s_stall_enc_ref 从 mode 31 启动就开始累计，把校准窗口的
   自由漂移混进第一个 500ms 窗，正确框架被 [IQPI_FLIP] 误翻。修复：
   - foc_iq_pi.c 加 s_loop_started——闭环首拍才对齐方向基准；
   - foc_lock_iq_pi.c 的 LOCKED_WAIT_HANDOFF 继续输出 90° 磁场吸住转子直到 31 接管。
3. **结论**：闭环启动一律走 mode 32 自动交接链（Watch 写 comm_mode=32）；
   mode 30+31 手动链只在转子恰好停在锚定位时碰巧可用。

## 十·五、mode 26 开环 VF 负载角实验（foc_olf.c/.h，2026-09-09 新增）

- **目的**：测同步电机功角特性。校准后磁场角匀速自增拖动，观察负载角
  delta = 磁场角 − 转子角随频率的变化，直至 90° 牵出失步。
- **流程**：进入自动跑 mode 25 式校准（BETA 2s → ALPHA 2s 锁零点，同框架
  Foc_Core_SetAlignOffset）→ 直接拖动（无刹车段）。**Vd=V 约定**
  （valpha=V·cosθ, vbeta=V·sinθ，磁场角=θ 本身，N 极对齐时 delta=0，
  与 mode 25 心智一致；注意 mode 30 是 q 轴约定磁场在 θ+90°，两者不同）。
- **与 mode 30 的本质区别**：mode 26 零点精确已知，id/iq 用**编码器真实
  转子角**做 Park（g_olf_id_ma/g_olf_iq_ma，实验核心观测量）；mode 30
  编码器只旁观锁偏移。
- **调频**：SW1 短按 +0.5Hz（main.c，与 mode 30 并列分支）；Watch 直改
  `g_olf_freq_hz`（阶跃生效）；重新进 mode 26 会复位 3Hz/0.6V（防残留
  高频启动即失步）。默认 3Hz/0.6V 与 mode 30 相同。
- **foc_obs 打印**：LOCKED 事件（offset→drag）+ 拖动中每 200ms
  `[OLF] f=mHz fld=deg rot=deg diff=deg id=mA iq=mA`（全整型）。
  仅 OC 自动回 mode 0。
- **实验预期**（理论探讨后确认）：delta 低频稳在 5~15°（摩擦锥，不是 0）
  → 频率升高缓升（BEMF 偷电压，电流变小）→ 逼近 90°（牵出边界，
  sinδ 峰值）→ 越过即锯齿崩塌振荡（失步）。id 低频≈0，高频转负
  （BEMF 去磁/电压饥饿 → 这就是真实 V/f 变频器按 V/f 比升压的原因）。
  iq=I·sinδ 随 delta 上升，失步后剧烈振荡。
- **接线**：dev_comm_runner.h `COMM_RUNNER_OLF=26`；.c 新 case + 全部 7 个
  旧 case 补 `Foc_Olf_Stop()`；foc.c ALIGN 分发第三优先级；foc.h 聚合。
  **foc_olf.c 需手动添加到 Keil 工程。**
