## 二、核心问题：mode 31 启动方向随机（未解决）

三个叠加原因，证据均来自 RTT 日志：

### 1. mode 30 偏移锁定不可复现（根因，未修）
- 同一台电机两次 lock：`-2142 mrad` vs `1098 mrad`，差约 186°；之前还锁出过 off≈0 的废值（当时 drag_dir=0）
- 采样窗口（100ms）内转子必须严格同步跟随磁场，打滑/卡滞 → diff 平均值乱落
- 待办 c：锁定合理性检查（窗口内 diff 方差过大或 drag_dir==0 → 拒绝锁定并重试），改 foc_zizeng.c

### 2. 编码器计数噪声雪崩（修复在 stash）
- 判据：CPR=4096（1024 线×4，见 encoder.h）、机械极限 7800rpm → 500ms 窗口位移上限 ≈ ±26.6 万 counts；
  实测出现过 `win=-312686`（=9150rpm，超物理极限）→ 噪声实锤
- 特征：pos 速率与 |vq| 强相关、两次 run 方向镜像 —— PWM 开关噪声耦合 PA8/PA9，
  mode 31 角度闭环正反馈放大成雪崩（角度飞转 → vq 顶格 → iq/id 混叠振荡）

### 3. 翻转后无软复位 → OC 急停（待办 b，改动小）
- 时间线：vq=3500（PI 积分器 windup 顶格）→ flip(+180°) → InvPark 电压矢量瞬间反向，
  积分器仍带 3.5V 旧指令 → 反向电压与 bemf 同向叠加 → 12.4A → OC 急停
- 待办 b：flip 分支内清 s_pid_id/s_pid_iq 积分器 + g_iqpi_iq_ref_ramp_ma 归零重新爬坡

## 四、日志判读速查

- IQPI_MON 各字段含义见 main.c 打印参数旁注释（已写）
- `ev=0`：方向检查从未运行过（窗口没攒满过）
- `|win| > 26 万`（500ms 窗）或 pos 速率 > 53 万 counts/s = 物理不可能 = 编码器噪声
- `[IQPI_FLIP] n=? pos=? ... off=?`：翻转事件快照，off 为翻转后基线（mrad）；cd=实测方向 ed=预期方向 rd=mode30 基准
- `st`：2=零矢量校准 3=闭环 4=vq饱和 5=堵转 6=过流 7=已翻转
- st=4 与 st=3 交替 = vq 在限幅附近振荡（电压不足/框架误差/噪声，需结合 pos 速率判读）
