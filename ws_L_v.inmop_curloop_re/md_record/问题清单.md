## P0 — mode 31 启动方向随机（时正转时反转）【未解决，当前最高优先级】

### 现象（RTT 日志实证）
- 同一台电机、同一流程，两次进 mode 31 转向相反
- **2026-09-06 用户澄清：mode 30 拖动 100% 恒逆时针（5/5 次 drag_dir=-1，从未顺时针）；
  随机性 100% 只出现在 mode 31** → mode 30 的拖动与方向基准本身可靠
- run 1 出现 `win=-312686`（500ms 窗，= 9150rpm，超机械极限 7800rpm）→ 编码器噪声实锤
- pos 速率与 |vq| 强相关；两次 run 方向呈镜像
- flip(+180°) 后 12.4A 触发 OC 急停（时间线：vq=3500 顶格 → flip → 电压矢量反向叠加旧积分器）
- ev 曾恒为 0（旧代码窗口被硬清零，方向检查从未运行——工作区已修复累积逻辑）
- **修正模型（2026-09-06）**：mode 31 方向不是逐次随机，而是"跟着上一次 mode 30 锁出的值走"
  （offset 跨 stop 保留）：好 lock≈1190 → 恒逆时针；坏 lock(-2142, 差191°) → 恒顺时针；
  废值≈0 → 转矩≈0 堵转。"时顺时逆"的真实粒度 = "上一次 mode 30 锁得好不好"

### 原因 1：mode 30 偏移锁定不可复现（根因，待修 = 任务 c）
- **现象**：两次 lock 出 `-2142 mrad` vs `1098 mrad`，差约 186°；更早还锁出过 off≈0 废值（当时 drag_dir=0）
- **推测**：100ms 采样窗内转子必须严格同步跟随磁场；打滑/卡滞/受扰 → diff 平均值乱落，
  锁出的基线本身带 0~186° 随机误差 → mode 31 的角度基准随机 → 转向随机
- **新增证据（2026-09-06 复测 5 次）**：lock = 1197/1177/1194/1186/1195 mrad，极差仅 20 mrad（±1°）
  → 锁定当前可复现，历史坏值判定为**偶发**（噪声 burst 砸进采样窗 / 转子恰好打滑）。
  任务 c 从"根因修复"降级为"保险丝"（方差 + drag_dir 检查，防偶发），仍建议做
- **修复方向**（foc_zizeng.c 锁定处，约 L291-313）：
  窗口内 diff 方差/极差检查 + drag_dir==0 拒绝锁定，打印拒因并重试（重新进 SAMPLING）
- **状态**：未开始

### 原因 2：编码器计数噪声雪崩（修复代码已丢失，待重写 = 任务 a）
- **现象**：见上 `win=-312686`；off 锁定值乱跳也可能有它一份（噪声同样污染 mode 30 的 diff 采样）
- **推测**：PWM 开关沿耦合进 PA8/PA9（CLKA/CLKB），振铃脉冲串被 4 倍频计数当成真实边沿；
  mode 31 角度闭环正反馈放大（角度飞转 → vq 顶格 → iq/id 混叠振荡）→ 雪崩
- **★ 敏感度换算（2026-09-06 新增，解释"小噪声也能反转"）**：
  pp=10、CPR=4096 → 90° 电角度 = 4096/4 = **102.4 counts（每圈 2.5%）**。
  mode 31 计数偏移累计 ±103 counts 转矩方向即翻转；mode 30 锁定窗前后被踢 ~103 counts，
  锁出偏移即带 >90° 误差（历史 -2142 坏值可能就是这么来的）。实测 avalanche 速率
  625k counts/s（31 counts/ISR），几百 µs 即可踢过门槛 → 噪声是偶发反转的头号嫌疑
- **修复方案**（已论证，见会话 2026-09-06）：
  1. TMRA 硬件滤波：`TMRA_SetFilterClockDiv` + `TMRA_FilterCmd`，CLA/CLKB 各 DIV64 = 640ns
     （PCLK1=100MHz 已核实；合法最坏半周期 1.88µs @7800rpm，裕量 3×；必须在 TMRA_Start 之后配置）
  2. 软件增量限幅：物理极限 32 counts/50µs-ISR（7800rpm=26.6，取整），Watch 可调 volatile；
     超限丢弃并计数（g_enc_delta_discards + 最后丢弃值），可见可查
  3. 回绕差分下沉 encoder.c 共用（现在 zizeng/iqpi 各一份重复代码），两模式都受益
- **旧实现疑点**：旧限幅 1500rpm(5 counts) 太紧，手拨/滑行/快加速合法超速被丢 → 永久角度误差，
  疑似即当时"编码器改动导致出问题"的原因；且丢弃不可见，坏了说不清现象
- **状态**：旧代码已丢失（stash 里没有，见"已核实事实"），需按上述参数重写

### 原因 3：翻转后无软复位 → OC 急停（改动最小，待修 = 任务 b）
- **现象**：flip 后 12.4A → OC（IQPI_STEP_FAULT_OC=6）
- **推测**：vq=3500 顶格说明 iq PI 积分器 windup；flip 把基线 +180° 后 InvPark 输出瞬间反向，
  积分器仍带 3.5V 旧指令，反向电压与 bemf 同向叠加 → 电流冲击
- **修复方向**（foc_iq_pi.c 翻转分支，约 L396-411）：翻转的同时
  `PID_Reset(&s_pid_id); PID_Reset(&s_pid_iq); g_iqpi_iq_ref_ramp_ma = 0.0f;` 重新爬坡
- **状态**：未开始

- **现象/推测**：惯性换向未完成时，下一窗口仍显示反向 → 立即翻回 → 帧随机、转向时对时错

- **动机**：与其给 mode 30 的拖动锁定打补丁，不如让 mode 31 的角度基准走"直流对齐"静态锁定
  （mode 23 同款原理）：转子被磁力静态吸到已知角度，物理上不存在打滑失步，N-S 方向由吸力唯一

  g_lockiq_win_evals / g_lockiq_track_err_cnts / g_lockiq_evt_code(1=锁定 2=超时 3=跟踪失败)
