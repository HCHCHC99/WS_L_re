版式（以 mode 40 为样板）：

```
 * ==============================================================================
 *   模式速览卡   MODE 40   编码器 FOC 速度/电流双闭环
 *   本卡是本模式唯一事实源；代码内注释与本卡冲突时，以本卡为准
 * ==============================================================================
 *   入口 / 前置 / 结束 / 标记
 * ------------------------------------------------------------------------------
 *   [可调] Watch 变量 -- 改值即时生效，复位后回宏默认
 *       变量                        当前值  单位     含义
 *       --------------------------- ------- -------- ---------------------------
 *       g_speed40_speed_target_rpm  0       rpm      目标转速（写它即给给定）
 * ------------------------------------------------------------------------------
 *   [只读] 关键观察变量
 * ------------------------------------------------------------------------------
 *   [VOFA 通道]，每通道一行
 * ------------------------------------------------------------------------------
 *   判据与坑
 * ==============================================================================
```

固定规则（生成器强制，不是靠人自觉）：

- 左侧独立标记列：`[!]` 易错点、`(*)` 主判据。扫左边缘就能找到关键行。
- 每个变量 / 每个 VOFA 通道**各占一行**，说明与条目同行；过长在说明列内折行、续行对齐。
- 全行 ≤ 78 列（Keil 里不用横向滚动）。
- **禁用宽度不确定字符**（`—` `→` `≥` `°` `±` `×` `·` `★` 等）。它们在 Keil 字体里宽度算不准，会让整列错位；一律用 `--` `->` `>=` `deg` `+/-` 代替。
- 描述列起始位置在同一段内唯一（51 / 33 / 44 三个位置）。

校验口径（每次 `--splice` 都跑）：
`vofa.rows.length == vofa.n` 且通道号严格 `ch0..ch(n-1)`；每个符号名在源码里真实存在（杜撰符号直接报错）；
符号是否来自本 mode 文件（来自公共模块只提示不算错）；行宽 / 列宽 / 禁用字符；注释配对；只改注释。

## 3. 核对中发现的问题（卡片按**代码**写，未按注释/文档写）

以下都是铺卡过程中对着源码逐条核出来的，**不是猜测**：

1. **mode 23 的"等编码器静止 300ms"判据形同虚设 —— 会覆盖共享零点**（→ 该模式已整模式删除，2026-09-26）
   `g_enc_count` 全工程只有 `foc_30_ramp.c:167` / `foc_31_iqpi.c:233` / `foc_32_lockiq.c:259` 三处写它，`encoder.c` 只读。
   mode 23 运行期间没人更新它 ⇒ `foc_23_align.c:113-126` 的静止判据恒成立，进 ALPHA 后固定 300ms 就锁 offset，
   取到的是**冻结残值**（本次上电没跑过 30/31/32 就是 0），会把 mode 20/24 的共享零点覆盖成 0。
   `foc_20_cal.h` 里"判据形同虚设"的注记与此一致。→ 处置：**删除整个 mode 23**（见第 6 节）。
2. **`g_foc_align_evt = 1` 永远不出现**：代码只置 2/3/4/5，`foc_obs.c:614` 的 `[ALIGN] start` 日志不可达。
3. **mode 26 默认值与文档不符**：代码初值 `0.2Hz -> 20s 爬到 150Hz`（自动扫频），
   而 `foc_26_olf.h` 旧卡写 0.5Hz、`md_record/交接.md` 写 3Hz/0.6V。卡片按 `.c` 写。
4. **mode 30 默认值与旧卡不符**：代码初值 `0.5Hz / 0.7V`，旧卡写 `3.0Hz / 0.6V`；
   `Start` 只在值 ≤ 0 时才改成 `5.0Hz / 0.6V`。
5. **mode 29 VOFA ch15 名不符实**：它是 `g_drun29_iq_pp_ma`（iq **反馈**峰峰值），
   不是 `.c:665` / 旧卡注释说的"iq 误差峰峰值"；误差 pp 是另一个变量 `g_drun29_eq_pp_ma`（`foc_29_drun.c:612`），且不在 VOFA 里。
6. **`FOC29_STEP_DEADBAND_MA` / `FOC41_STEP_DEADBAND_MA` 是死宏**：定义后无人引用（全工程 0 处代码引用），
   阶跃测量真正的武装条件只有 `|ref| >= FOC29/41_STEP_MIN_MA`（100mA）。
   → **2026-09-26 已删除这两个宏**，并把 `.h` 里描述旧算法（"与上一拍参考之差"）的注释改写为现行算法
   （武装 = 进模式后第一次 `|ref| >= 100mA`；测量 = `|actual|` 首次达到 `step_frac_pct% × target` 并连续保持
   `STEP_CONFIRM_TICK` 拍）。注释里留了一行"何时删的、为什么删"，避免以后有人又从旧文档把它加回来。
7. **`g_drun29/41_step_frac_pct` 名不符实**：声明初值 90，进模式时被 `ClearObservables` 写成 75，
   所以 `*_iq_step_t90_us` 实际是 **75%** 上升时间。
8. **mode 32 的 ch12 是陷阱**：读的是 mode 31 的 `g_iqpi_theta_rad`，吸附期间是陈旧值；
   mode 32 自己的磁场角写在 `g_foc_theta_rad`，没进任何 VOFA 通道。
9. **mode 28 初值与注释不符**：`g_dci_volt_v` 初值 0.8 但 Start 复位 0.6（卡写 0.6）；
   `g_dci_dlt_init_deg` `.h` 注释写"默认 5"，实际 `.c` 初值 90（卡写 90）。
10. **mode 45 文档与代码不符**：`SMO调参与验收记录.md` 写判定门限 ≥1300rpm，代码是 `g_smo_jdg_rpm_min = 900.0f`；
    记录写"回落 17ch 通用布局"，代码 `Foc_Common_VofaFill` 返回 20。卡片按代码写。
11. **mode 45 是变长帧**：`g_smo45_wave_mode` = 0 → 16ch（SMO 验收面板）、= 1 → 8ch（波形窄帧）、= 2 → 16ch（PLL 面板），
    三个分支通道含义互不相同。切布局时 VOFA+ 上位机通道数必须跟着改。
    实测踩过的坑：没先跑 mode 24 时 mode 45 起不来，固件回落到 20ch 通用帧而上位机仍按 16ch 解析
    （ch13 读成 0.004、ch15 在 ±100deg 乱跳），看起来像观测器炸了。
12. **`main.c` 的 `comm_mode` 注释严重过期**（原文只列 `0/23/30/31/32`）。
    已换成完整取值总览，并指向各模式头文件的卡。
13. **mode 31 的 SW3 短按有 bug**：`main.c:268-278` 里 `!= 31` 先把 `comm_mode` 置 31，紧接着 `== 31` 分支又置回 0
    ⇒ 按键实际只能停机，进 31 只能靠 Watch 写或 mode 32 交接。
14. **mode 30 的 ISR 内没有过流判据**：全 `ws/` 里只有 `foc_30_ramp.c` 不调 `Foc_Core_OverCurrent`
    ⇒ 别随手加大 `g_zizeng_volt_v`；退出只能靠 SW2 / `comm_mode = 0`。
15. **mode 30 的方向阈值有个数字陷阱**：`FOC30_DRAGDIR_MIN_CNTS = ENCODER_CPR/50 = 81 counts`，
    而 100ms 锁定窗内 0.5Hz 只走约 20 counts ⇒ `drag_dir` 恒 0，看着像"锁定失败"（要提到 ≥2Hz）。
    更麻烦的是它会让 mode 31 的方向自检整段跳过，转向错了也不会被纠正。
16. **mode 31 的入口来自交接**：mode 32 锁定成功会自动调 `Foc_IqPi_Start`（`foc_obs.c:693`）切进 31。
17. **电流环 kp 过小实测门槛**：`kp=0.05` 时电机纹丝不动（P 环输出克服不了铜阻压降），
    P-only 的可动门槛约 `(3~7) x R = 0.5~1 V/A`（mode 28 / 41 的 `(*)/([!])` 注里）。
18. **mode 30 的默认值同样与旧卡不符**：代码初值 `0.5Hz / 0.7V`，旧卡写 `3.0Hz / 0.6V`（与第 4 条同源问题）。

## 5. mode 45 的环路增益对齐 mode 40（2026-09-26）

### 对比结论

mode 40 与 mode 45 的**有感段**是同一台电机、同一套电流采样、同一段控制代码
（同样的 5 ms 速度环 + 每拍电流环、同样的滤波与限幅写法），差别只有 3 个数字：

| 项 | mode 40（定稿） | mode 45（改前） | 倍数 |
|---|---|---|---|
| 电流环 kp | 0.1 V/A | 0.5 V/A | 5× |
| 速度环 kp | 0.8 mA/rpm | 1.8 mA/rpm | 2.25× |
| 速度环 ki | 0.03 mA/rpm/s | 0.2 mA/rpm/s | 6.7× |
| 其余（ki 电流环 300 / UMAX 6.2V / ITERM 6.0V / iq 滤波 0.10 / 速度窗口 5ms / 速度滤波 0.25 / 显示 0.05 / iq 限幅 3400mA / 加速度限幅 1950rpm/s / 编码器增量限幅 36） | — | — | **完全相同** |

### 这两组数的来历（源码注释即证据）

- mode 45 电流环原文 "*start from the verified **mode 29** values*" ⇒ 0.5/300 是 mode 28/29/41 的家族默认值，不是为 45 调的。
- mode 40 电流环：2026-09-23 为压静止噪声专门从 0.5 降到 0.1（实测 0.5 明显噪声、0.05 与 0.1 无差别）。
- mode 40 速度环调参轨迹 `kp 1.8 → 4.0 → 2.0 → 0.8`、`ki 0.2 → 0.45 → 0.01 → 0.03`。
  ⇒ **mode 45 改前的 1.8 / 0.2 正好是这条轨迹的第 0 步。**

### 量的含义（不是"稳不稳"，是"快慢与噪声"）

| 指标 | kp=0.1 | kp=0.5 |
|---|---|---|
| 电流环带宽 ωc = kp/L | 2364 rad/s = 376 Hz | 11820 rad/s = 1.88 kHz |
| 闭环时间常数 L/kp | 423 µs | 85 µs |
| 闭环阻尼 ζ=(R+kp)/(2√(ki·L)) | 0.89（接近临界） | 2.66（过阻尼） |
| 相位裕度（Td=25µs 线性模型） | ≈80° | ≈81° |

⇒ 两者的稳定性都不差，0.5 的代价是**静止噪声**（开关纹波 × P 增益 → 占空比被推偏 → 正反馈极限环）。

### 已做的改动

`ws/foc_45_smo.h`：`FOC45_PI_KP 0.5→0.1`、`FOC45_SPD_KP 1.8→0.8`、`FOC45_SPD_KI 0.2→0.03`，
并在宏上方补了改动理由与教训注释（原本那里只有一行 "Outer speed PI..." 没有任何调参记录）。
mode 45 特有的部分未动：`g_smo45_ang_lead_ticks` 角度超前、无感锁存后速度反馈切 `g_pll_omega_out_rpm`、auto ramp。
卡片（`foc_45_smo.h` 顶部速览卡）的 Watch 默认值与 notes 已同步更新。

### 待验证

- 静止（目标 0）下是否真的安静了（对比改前的 kp=0.5）。
- 0→1000 rpm 阶跃的超调/上升时间是否与 mode 40 一致（预期 4.1% / 600ms 量级）。
- **无感段**（`g_smo45_sl_active=1`）速度反馈换成 PLL 估计，噪声特性与编码器不同；
  若切无感后抖动，应单独议外环参数，不要直接套有感段的结论。
