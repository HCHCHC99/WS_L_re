## 一、为什么要拆分

mode 28 是"校准 + 闭环"一体化：校准吸附阶段转子会动（BETA/ALPHA 各 2s 电压开环），
**捏转子的时机很难掌握**——捏早了影响校准，捏晚了转子已经转起来。

拆分后：

| 模式 | 变体 | 职责 | 结束状态 |
|---|---|---|---|
| mode 24 | `DCI_VARIANT_CAL` | 仅校准（零偏窗 + BETA + ALPHA + 锁双帧） | 自动回 mode 0，转子自由 |
| mode 29 | `DCI_VARIANT_RUN` | 仅电流环（复用已锁参数，直接 RUN） | 运行中 |

两模式共用 `foc_dci.c/h` 同一套状态机/参数/观测量，靠 `g_dci_variant` 区分。

## 二、mode 24：仅校准

入口 `Foc_Dcal24_Start()`（comm_mode=24）。流程与 mode 28 校准段完全一致：

1. **DCI_STEP_CALIB**：零矢量 50/50/50，~210ms，锁三相零偏 `g_calib_*_off_ma`
2. **DCI_STEP_CAL_BETA**：磁场 90° 吸附 2s
3. **DCI_STEP_CAL_ALPHA**：磁场 0° 吸附 2s → 锁双帧零点：
   - 显示帧 `g_dci_offset`（绝对帧，跨模式可比）
   - 控制帧 `s_off_rel`（相对帧，RUN 控制系零点）
4. **完成**：置粘滞标志 `g_dcal_offset_valid=1` → 发 `DCI_EVT_CAL24_DONE` →
   foc_obs 打印 `cal-only (mode 24) done ... back to mode 0` → **自动 PwmStop 回 mode 0**

### 校准后转子可以随便动（关键认知）

- 电流零偏：与转子位置无关（传感器零点）
- 编码器零点 `g_dci_offset`：固定零点基准，转子移动后基准依然成立
- TMRA_1 硬件计数器 free-run 不停，手转不丢计数；mode 0 下
  `Foc_Core_UpdateAngleObs()`（foc_obs 主循环每圈调用）持续刷新
  `g_foc_mech_deg` / `g_foc_elec_deg` —— 转子位置实时可见

## 三、mode 29：仅电流环

入口 `Foc_Drun29_Start()`（comm_mode=29）。

### 前置检查

```c
if (!Foc_Calib_IsLocked() || (g_dcal_offset_valid == 0u)) {
    ERROR: calib/offset not locked, run mode 24 (or 28) first   // 拒绝启动
}
```

### 编码器帧重锚定（吸收校准后的一切转子移动）

Start 瞬间读当前硬件计数，重建控制帧：

```c
hw_now    = TMRA_GetCountValue(CM_TMRA_1);
rel_start = mod(hw_now × dir − g_dci_offset, CPR);   // 当前真实相对电角
s_enc_pos = 0;
s_off_rel = mod(−rel_start × dir, CPR);              // 此刻转子电角 = 实际相对电角
```

**无论校准后把转子捏动到哪、捏多少次，mode 29 启动那一刻都以当前位置为
起点重建帧，微动被完全吸收**。第一拍磁场方向即正确对准转子。

### RUN 电流环（与 mode 28 逐拍等价）

每拍：编码器增量（±32 限幅）→ 转子角 → Park 得 id/iq → 参考生成 →
PI（当前 i_valid=false 纯 P）→ 反 Park（转子角）→ SVPWM。

## 四、标准工作流（P 重调）

```
1. comm_mode=24          → 等 RTT "cal-only (mode 24) done"
2. mode 0 捏转子          → Watch 看 g_foc_elec_deg 稳定（想捏多紧捏多紧）
3. comm_mode=29          → 直接进电流环，BEMF=0（纯 R+L 对象）
4. kp 扫参（Watch 改 g_dci_pid_*_cfg.kp）：0.5 → 1.0 → 2.0
   判据：快速爬到稳态平台，平台上方不振铃（eq_pp 不发散）
   注意：P-only 稳态值 = kp/(kp+R)·i_ref（kp=0.5 时 77%），落差是理论必然
5. P 合格后：Watch 置 i_valid=1 + ki=300（DCI_PI_KI）→ eq_mean → 0±50mA
```

### 阶跃激励设置（当前默认已配好）

```
g_dci_dlt_init_deg = 90    g_dci_dlt_targ_deg = 90    g_dci_dlt_tr_ms = 0
```

δ 直达 90°（tr=0 时 w=1 直通），启动第一拍 iq_ref 即满值——阶跃输入，
P 强弱一眼可见。VOFA 采样 ~11ms 远慢于电气时间常数，爬升沿看不见，
**看平台高度 + 平台上方振铃 + eq 统计**。

## 五、I_ref 软启动斜坡（本次新增）

调 P 需要阶跃，但推杆应用需要"最终目标定下来、参考一拍一拍爬"。新增：

```c
#define DCI_I_RAMP_MA_S   0.0f   /* mA/s；<=0 = 直通（阶跃），>0 = 软启动 */
```

| 项 | 说明 |
|---|---|
| 生效机制 | 每拍 step = 斜率/20000，`s_i_ref_ramp` 向 `g_dci_i_ref_ma` 挪一步到顶夹住 |
| 斜坡对象 | **电流矢量幅值**（δ=90° 时 iq_ref 跟随幅值爬升），id/iq 不分别斜坡 |
| Start 行为 | `s_i_ref_ramp=0`，启动即从 0 爬坡（软启动天然包含） |
| 运行中改目标 | 按斜率跟随，不突跳 |
| Watch | `g_dci_i_ramp_ma_s` 实时可调；`g_dci_i_ref_ma` 恒为最终目标 |
| VOFA | CH12/CH13 显示斜坡后参考，可直接看到小目标轨迹 |
| 误差统计 | ed/eq 自动对斜坡后参考计算，判据不受影响 |

斜率 >0 与 δ 爬坡叠加时：先各自成形再相乘，iq_ref = ramp(I)·sin(δ)。

## 六、Watch 变量速查

| 变量 | 说明 |
|---|---|
| `g_dci_i_ref_ma` | 最终电流幅值目标 (mA)，Start 不复位 |
| `g_dci_i_ramp_ma_s` | 软启动斜率 (mA/s)，<=0 阶跃 |
| `g_dci_dlt_init/targ/tr` | δ 爬坡三参数（当前 90/90/0 阶跃配置） |
| `g_dci_pid_id_cfg / iq_cfg .kp/.ki/.i_valid` | PI 参数，volatile 实时生效 |
| `g_dcal_offset_valid` | 校准 offset 粘滞标志（1=可进 mode 29） |
| `g_dci_variant` | 当前变体（1=CAL/0=FULL/2=RUN） |
| `g_foc_elec_deg` | mode 0 下实时转子电角（捏转子对位用） |
| `g_dci_iq/id_ma`、`g_dci_iq/id_ref_ma` | 反馈/参考实时值 |
| `g_dci_eq/ed_mean_ma`、`eq/ed_pp_ma` | 5s 误差均值/峰峰值（P 调参主判据） |
| `g_dci_vsat` | 电压饱和标志（=1 时调参数据作废） |
